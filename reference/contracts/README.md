# Proof of One — reference smart contracts

> **Reference code for review and testing only. Not audited. The verifier is generated from a TEST-ONLY trusted setup — do not deploy.**

`ProofOfOnePolls.sol` combines the poll, ballot and result roles described in [`docs/specs/contracts-v0.1.md`](../../docs/specs/contracts-v0.1.md) for a 4-option poll. It accepts a ballot only with a valid zero-knowledge proof from [`../ballot-circuit`](../ballot-circuit/), and it accepts a result only if it passes the checks the contract can make on its own.

## What the contract enforces

| Rule | Where |
|---|---|
| The tally key is on Baby Jubjub and in the prime-order subgroup (checked once per poll) | `createPoll` → `BabyJubjub.isInSubgroup` |
| Polls are open for at least 48 hours (room for forced inclusion) | `createPoll` |
| Every ballot carries a valid π_vote proof | `vote` |
| Public inputs are rebuilt from the poll's own parameters, never taken from the caller | `vote` |
| Proofs are bound to this chain, this contract and this poll (`contextHash`) | `vote` |
| Latest ballot per nullifier, re-vote cap, count of distinct voters, ordered ballot chain | `vote` |
| No ballots outside the open period | `vote` |
| A result must match the ballot chain | `publish` |
| Totals must equal the number of distinct voters (one-hot ballots) | `publish` |
| Voters must not exceed eligible identities | `publish` |
| A 7-day challenge period applies before a result becomes final | `finalize` |
| Anyone may mark a result "withheld" if it is not published within 14 days | `markWithheld` |

Ballot ciphertexts are **not** checked for subgroup membership on-chain. The proof computes them from Base8 and the already-validated tally key, so they are in the subgroup by construction. This saves a large amount of gas per ballot.

## Not yet implemented

- IdentityRegistry and RevocationRegistry, including batch insertion. In this reference, the poll creator supplies the snapshot roots.
- Trustee signatures on the tally key and on results. In this reference, the poll creator publishes the result.
- On-chain challenges (DLEQ failure, aggregate mismatch). These are checked off-chain by the recount tool in [`../tally`](../tally/).
- Relay (ERC-4337), breakdown cells, ballot aggregation, governance.

## Run it

```bash
# requires ../tally and ../ballot-circuit installed and built (see their READMEs)
npm install
npm test        # compiles with solc-js, then runs end-to-end tests on an in-process EVM
```

## Tests

The tests run on ganache, an in-process EVM. They use **real** Groth16 proofs and real encrypted ballots.

| Test | Expected result |
|---|---|
| Tally key outside the subgroup or off the curve | Poll creation rejected |
| Poll shorter than 48 hours | Rejected |
| Valid ballots and a re-vote | Accepted; the later ballot replaces the earlier one |
| Proof attached to different ciphertexts | Rejected (`InvalidProof`) |
| Proof replayed in another poll | Rejected (`InvalidProof`) |
| More re-votes than the cap | Rejected |
| On-chain ballot chain vs the chain rebuilt by the reference tally from events | Identical |
| Ballot after close | Rejected |
| Tally of real ballots | Correct |
| Totals that do not add up, or a wrong chain | Result rejected |
| Finalising before the end of the challenge period | Rejected; accepted afterwards |
| Unpublished poll after 14 days | Marked withheld |

## Measured gas (reference, unoptimised)

| Operation | Gas |
|---|---|
| `createPoll` (including subgroup check of the tally key) | 614,472 |
| `vote`, first ballot | 533,595 |
| `vote`, re-vote | 442,953 |
| `publish` | 158,052 |

A first ballot costs more than the spec's estimate of about 420,000. The main costs are Groth16 verification with 26 public inputs and the ballot event data. Hashing the public inputs into one value, and ballot aggregation, are the planned reductions.
